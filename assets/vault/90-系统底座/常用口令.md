# 常用口令

复制下面的话发给你常用的 Agent。查资料用哪个 Agent 都可以，批量整理固定交给同一个。

## 每天随手记，十秒

这一步不用口令。网页用官方 Web Clipper 存进 `00-收件箱`，顺手写一句为什么收。想到什么就在 Obsidian 按 `Cmd + N`（Windows 是 `Ctrl + N`），新笔记会直接建在收件箱，写完就关，先不分类。

## 每周清收件箱，两分钟

攒到五到十篇，或者到了每周固定的那天：

> 检查 `00-收件箱`，按 `AGENTS.md` 给我一份归档预览清单，标出每篇建议去哪个目录、需要补什么属性、和现有笔记有没有冲突。等我确认后再执行。

看完清单回一句：

> 确认执行

收件箱积压太多时，不用逐条分：

> 把 `00-收件箱` 里一个月前的笔记整批列出来，建议移到 `80-已归档`，不逐条分类。先给清单，等我确认。

## 项目做完，提炼经验再归档

> 把 `10-进行中/项目名` 里能跨项目复用的经验提炼成一张知识卡片，放进 `20-专业沉淀`，原项目移入 `80-已归档`，同步更新 `SOURCE_OF_TRUTH.md`。先给清单，等我确认。

## 决定有了结果，回填

> 找到 `30-决策与复盘` 里关于「主题」的那条记录，把这个实际结果补进「后来发生了什么」：……保留当时的判断，给我笔记路径。

## 每月体检，只读

觉得找东西变慢了也可以随时做：

> 只读检查整个库，看看有没有失效链接、互相冲突的版本，`SOURCE_OF_TRUTH.md` 是否太长需要瘦身。不要改文件，列一份清单给我。

## 把对话沉淀进库

> 把我们刚才确认的决定、原因和待验证的事项，写进这个知识库。给我新笔记的路径。

## 两条底线

- 批量整理只交给一个主力 Agent。两个 Agent 同时移动或修改文件，一个刚把笔记挪走，另一个还按旧路径改，链接就会断。
- 大整理前留一个恢复点。库是 Git 仓库就先提交一次；不用 Git 就先把整个库文件夹复制一份。
